# Zvuk Music 1.8.4 Release Design

## Goal

Publish the completed setup-flow, lazy-recommendation, and upstream-sync fixes as the stable provider release `1.8.4`.

## Scope

- Change `VERSION` from `1.8.3` to `1.8.4`.
- Keep the existing `CHANGELOG.md` entry for `1.8.4` unchanged because it already describes the merged user-visible changes.
- Do not modify provider runtime code, tests, dependencies, or generated workflow wrappers.

## Release Flow

The change lands through a pull request targeting `dev`. The repository version guard validates that only the maintainer-owned release version changes. After merge, the existing pipeline detects the new stable PEP 440 version and performs the configured tag and publication steps.

## Validation

- Confirm `VERSION` contains exactly `1.8.4` followed by a newline.
- Run the full test suite.
- Run all pre-commit hooks, including lint and type checking.
- Verify the PR CI and version guard complete successfully.
- Verify the post-merge release pipeline before reporting completion.

## Failure Handling

If any local or remote validation fails, do not merge. Diagnose the failing check, apply only an in-scope correction on the release branch, and repeat the complete validation relevant to that correction.
